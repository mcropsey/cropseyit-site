RHCSA Cheat Sheet EX200 · RHEL 9 / 10 ← Full workbook

RHCSA quick reference

Every command from the 25-lab workbook, regrouped by exam objective instead of lab order. Each card links back to the lab that drills it.

The seven rules that decide your scorefront matter

1. Graded after rebootMake the change, verify it, then reboot and verify again. Anything that doesn't survive a reboot scores zero.
2. Guard every fstab editRun findmnt --verify before any reboot that follows an /etc/fstab change. One bad line drops the box into emergency mode.
3. Never disable SELinuxRead the denial, then fix the label, port, or boolean. setenforce 0 is a diagnostic, never a fix.
4. Persistent, not temporarysemanage + restorecon over chcon; firewall-cmd --permanent + --reload; systemctl enable --now, not just start.
5. Docs are on the examman <cmd>, man 5 <file>, the EXAMPLES section of man semanage-fcontext, and /usr/share/doc/.
6. Match UIDs across hostsCreate users in the same order on both servers. NFS maps ownership by number, not name.
7. Snapshot before you break thingsSnapshot both servers after Lab 1, and again before Lab 3.

Reboot-survival checklist

sudo findmnt --verify     # fstab is syntactically sane
systemctl is-enabled httpd nfs-server chronyd autofs
sudo semanage fcontext -l -C # your custom file-context rules (-C = local only)
sudo semanage port -l -C  # your custom port rules
swapon --show; df -h      # swap and mounts are live
sudo ausearch -m avc -ts boot # want: <no matches>

NetworkingLab 1

Find the real connection name first

nmcli con show
nmcli -t -f NAME,DEVICE con show --active
CON="ens160"   # often the device name, not "Wired connection 1"

Static address + hostname

sudo hostnamectl set-hostname servera.lab.local
sudo nmcli con mod "$CON" ipv4.addresses 192.168.1.95/24 ipv4.gateway 192.168.1.1 \
  ipv4.dns "1.1.1.1 8.8.8.8" ipv4.method manual connection.autoconnect yes
sudo nmcli con up "$CON"

# duplicate-safe /etc/hosts
grep -q servera.lab.local /etc/hosts || sudo tee -a /etc/hosts <<'EOF'
192.168.1.95 servera.lab.local servera
192.168.1.96 serverb.lab.local serverb
EOF

Verify

ip -4 addr show
nmcli -g ipv4.method,ipv4.addresses,ipv4.gateway,ipv4.dns con show "$CON"
hostnamectl; cat /etc/resolv.conf; ping -c 2 serverb

Warning: over SSH, nmcli con up kills your session when the address changes. Run it from the console.

  • Set ipv4.addresses in the same command as (or before) ipv4.method manual — manual with no address is rejected.
  • RHEL 9/10 store keyfiles in /etc/NetworkManager/system-connections/. ifcfg is deprecated in 9, gone in 10 — use nmcli/nmtui.
  • IPv6 variant: ipv6.addresses fd00::95/64 ipv6.method manual

firewalldLabs 2, 3, 6, 9

sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --permanent --add-port=82/tcp
sudo firewall-cmd --permanent --add-service={nfs,mountd,rpc-bind}
sudo firewall-cmd --reload         # REQUIRED after --permanent
sudo firewall-cmd --list-all
sudo firewall-cmd --list-services

# debug: log the drops, then watch the kernel ring
sudo firewall-cmd --set-log-denied=all
sudo journalctl -k --since "-5min" | grep "DPT=82" | tail
sudo journalctl -k -f | grep --line-buffered "DPT=82"
sudo firewall-cmd --set-log-denied=off # cleanup

Key trap: firewalld does not filter loopback. curl http://localhost:82 succeeds even with the port closed — always test from the other server.

  • Firewall changes never need a service restart.

SELinuxLabs 3, 18, 23

Status & tooling

getenforce; sestatus; grep ^SELINUX= /etc/selinux/config
sudo dnf -y install policycoreutils-python-utils setroubleshoot-server
policycoreutilspreinstalled: restorecon, getenforce, setenforce
…-python-utilssemanage, audit2why, audit2allow
setroubleshoot-serversealert + plain-English AVCs in the journal
auditdwrites AVCs to /var/log/audit/audit.log

Read the denial — three ways

sudo ausearch -m avc -ts recent -i     # "recent" = last 10 minutes
sudo ausearch -m avc -ts recent | sudo audit2why # SELinux explains the cause
sudo sealert -a /var/log/audit/audit.log # analysis + suggested fix
sudo journalctl -t setroubleshoot --since "-10min"

Fix a file-context denial

ls -Zd /webdata                        # default_t = wrong
sudo semanage fcontext -a -t httpd_sys_content_t "/webdata(/.*)?"
sudo restorecon -Rv /webdata
# or clone the rules of an existing path:
sudo semanage fcontext -a -e /var/www /webdata

Fix a port denial

sudo semanage port -l | grep -w http_port_t
sudo semanage port -a -t http_port_t -p tcp 82

Traps: chcon survives only until the next relabel — use semanage fcontext + restorecon. And mv preserves context while cp inherits the target's, so a file moved from ~ keeps user_home_t. Check with ls -Z.

Software management & reposLab 2

Mount the ISO, serve it over HTTP

sudo mkdir -p /var/www/html/rhel
sudo mount -o loop,ro /root/rhel.iso /mnt
sudo cp -a /mnt/. /var/www/html/rhel/ # ~10 GB; check free space
sudo umount /mnt
sudo restorecon -Rv /var/www/html  # cp -a kept the ISO's labels

Repo file (the only shape worth memorising)

sudo tee /etc/yum.repos.d/lab.repo <<'EOF'
[lab-baseos]
name=Lab BaseOS
baseurl=http://192.168.1.95/rhel/BaseOS
enabled=1
gpgcheck=1
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-redhat-release
[lab-appstream]
name=Lab AppStream
baseurl=http://192.168.1.95/rhel/AppStream

gpgcheck=1

sudo dnf clean all
sudo dnf repolist

Verify & troubleshoot

curl -sI http://192.168.1.95/rhel/BaseOS/repodata/repomd.xml | head -1
sudo dnf repolist -v | grep -E 'Repo-id|Repo-pkgs'
sudo dnf info nfs-utils | grep -i repo # which repo would serve it
sudo dnf --disablerepo=<id> install ... # skip a broken repo
sudo dnf config-manager --disable <id>
sudo rpm --import /etc/pki/rpm-gpg/RPM-GPG-KEY-redhat-release

Two classic errors: $releasever and $basearch are dnf variables — in a shell command like mkdir or curl they expand to nothing. And dnf config-manager --add-repo writes no gpgkey= line, so installs fail the signature check until you add it.

  • One failing third-party repo stops every dnf command. Use gpgcheck=0 only when the task says so.

Apache (the SELinux set-piece)Lab 3

The full exam pattern: move the root → hit a label denial → fix it → change the port → hit a port denial → fix it → open the firewall → reboot and re-verify.

# /etc/httpd/conf/httpd.conf -- CHANGE the existing DocumentRoot,
# don't add a second one; then add the matching Directory block.
DocumentRoot "/webdata"
<Directory "/webdata">
    AllowOverride None
    Require all granted
</Directory>
Listen 82
sudo apachectl configtest    # expect "Syntax OK" -- always before restart
sudo systemctl restart httpd
sudo ss -tlnp | grep :82
systemctl status httpd --no-pager
# then: sudo semanage fcontext ... ; sudo semanage port ... ; sudo firewall-cmd --add-port
  • mv /etc/httpd/conf.d/welcome.conf /root/welcome.conf.bak so a 403 shows as a 403, not the Red Hat test page.
  • Never systemctl restart auditd (the unit refuses). Use service auditd restart.

Users, groups & agingLabs 4, 11, 13, 14

Create

sudo groupadd admin
sudo useradd -G admin harry              # supplementary group
sudo useradd -s /sbin/nologin sarah      # no interactive shell
getent passwd 6969 || sudo useradd -u 6969 billy # check the UID is free

# non-interactive passwords (the exam-safe way)
printf '%s\n' 'harry:Harry123' 'natasha:Natasha123' | sudo chpasswd
echo 'billy:Billy123' | sudo chpasswd

Verify

id harry; getent group admin
getent passwd sarah | cut -d: -f7   # /sbin/nologin
sudo su - sarah                     # "account is currently not available"

Password aging

# default for FUTURE users only
sudo sed -ri 's/^PASS_MAX_DAYS\s+.*/PASS_MAX_DAYS\t20/' /etc/login.defs

sudo chage -l harry            # inspect
sudo chage -M 20 harry         # max days, existing user
sudo chage -d 0 natasha        # force change at next login
sudo chage -E 2026-12-31 billy # account expiry date

umask

echo 'umask 027' | sudo tee -a /home/natasha/.bashrc # one user -> 640 / 750
echo 'umask 027' | sudo tee /etc/profile.d/umask.sh # all users
sudo su - natasha -c 'umask; touch ~/t; mkdir ~/d; ls -ld ~/t ~/d'

Traps: usermod -G replaces every supplementary group — use usermod -aG to append. /etc/login.defs never touches existing accounts. Use .bashrc (not .bash_profile) for umask, since RHEL's profile sources it for both login and non-login shells.

  • Changed a UID with usermod -u? Files outside the home directory keep the old number. Find them with find / -xdev -nouser.

Permissions, SGID & ACLsLabs 5, 8

Collaboration directory

sudo mkdir -p /srv/common_admin
sudo chgrp admin /srv/common_admin
sudo chmod 2770 /srv/common_admin # 2 = SGID: new files inherit the group
sudo chmod 3770 /srv/common_admin # +sticky: members can't delete each other's
sudo setfacl -m d:g:admin:rwx /srv/common_admin # default ACL beats any umask
ls -ld /srv/common_admin          # drwxrws--- root admin

ACLs

sudo chmod 644 /var/tmp/fstab
sudo setfacl -m u:harry:rw- /var/tmp/fstab
sudo setfacl -m u:natasha:--- /var/tmp/fstab
getfacl /var/tmp/fstab
ls -l /var/tmp/fstab              # note the trailing "+"

sudo setfacl -x u:natasha /var/tmp/fstab # remove one entry
sudo setfacl -b /var/tmp/fstab        # remove all ACLs
u: / g:user / group entry
d:default (inherited by new children; directories only)
-m / -x / -bmodify / delete one / wipe all

Mask trap: chmod g-w on an ACL'd file changes the ACL mask, which can silently strip a user's write. Look for #effective: in getfacl output.

  • Use /var/tmp, not /tmp, for anything that must still exist at grading time.

sudoLab 15

echo '%admin ALL=(ALL) NOPASSWD: ALL' > /tmp/admin
sudo visudo -cf /tmp/admin           # expect "parsed OK" -- check BEFORE installing
sudo install -m 440 /tmp/admin /etc/sudoers.d/admin
sudo su - harry -c 'sudo -n id'      # -n = fail, don't prompt
  • sudo -n is the only honest test that a rule is truly passwordless.
  • A broken drop-in breaks sudo for everyone. Including yours: check the file in /tmp first, or use sudo visudo -f /etc/sudoers.d/admin, which refuses to save a broken file.
  • sudo ignores files in /etc/sudoers.d whose names contain a dot or end in ~.
  • Variants: usermod -aG wheel user (sudo with password); %admin ALL=(ALL) /usr/bin/systemctl (one command).

LVM & growing storageLabs 19, 20, 25

Partition a new disk for LVM

lsblk                       # find the empty disk: vdb / sdb / nvme0n1
DISK=/dev/vdb
sudo parted -s $DISK mklabel gpt
sudo parted -s $DISK mkpart lvm1 1MiB 1025MiB
sudo parted -s $DISK set 1 lvm on
sudo parted -s $DISK mkpart lvm2 1025MiB 100%
sudo parted -s $DISK set 2 lvm on
sudo udevadm settle
lsblk $DISK                 # NVMe names are nvme0n1p1 / p2

PV → VG → LV → filesystem

sudo pvcreate ${DISK}1 ${DISK}2
sudo vgcreate -s 8M datastore ${DISK}1 ${DISK}2 # -s = PE size
sudo lvcreate -L 500M -n database datastore  # rounds up to 504M (63 x 8M)
sudo lvcreate -l 60 -n database datastore    # -l = 60 extents = 480M exactly
sudo mkfs.xfs /dev/datastore/database
sudo pvs; sudo vgs; sudo lvs
sudo vgdisplay datastore | grep 'PE Size'

Extend

sudo vgs datastore                             # check VFree FIRST
sudo lvextend -l +100 -r /dev/datastore/database # +100 extents, grow FS too
sudo lvextend -L +100M -r /dev/datastore/database # by size
sudo lvextend -L 1.5G  -r /dev/datastore/database # to absolute size
sudo lvextend -r -l +100%FREE /dev/rhel/root    # take everything left

# out of space in the VG? add a disk:
sudo pvcreate /dev/vdc; sudo vgextend datastore /dev/vdc

Grow / after the hypervisor disk was enlarged

Memory anchor: disk → growpart → pvresize → lvextend -r. Every layer has to grow, in that order.

lsblk; df -h /; sudo pvs; sudo vgs              # 0. before
echo 1 | sudo tee /sys/class/block/sda/device/rescan # 2. SCSI/SATA rescan
sudo dnf -y install cloud-utils-growpart         # 3. grow the partition
sudo growpart /dev/sda 3
#   alt: sudo parted /dev/sda resizepart 3 100% (answer Yes), then sudo partprobe
sudo pvresize /dev/sda3                          # 4. grow PV
sudo vgs                                         #    VFree > 0 now
sudo lvextend -r -l +100%FREE /dev/rhel/root     #    grow LV + FS
SymptomCauseFix
lsblk shows old sizeKernel hasn't rescannedRescan the device, or reboot
pvresize: no changePartition wasn't growngrowpart / resizepart first
insufficient free extentsPV not resizedpvresize
resize2fs: bad magic numberIt's XFS, not ext4lvextend -r or xfs_growfs /
growpart can't grow itNot the last partitionAdd a disk: pvcreate → vgextend → lvextend -r
Hypervisor won't resizeSnapshots existDelete or merge them first

Warning: never build an exam VG on loop devices — they don't come back after a reboot, the fstab entry fails, and the server lands in emergency mode. If you must, add nofail, then losetup + vgchange -ay after each boot.

  • -r grows the filesystem in the same step (xfs_growfs for XFS, resize2fs for ext4).
  • XFS cannot shrink. ext4 can, offline: lvreduce -r -L 400M ...

Filesystems & /etc/fstabLabs 6, 18, 19

sudo mkfs.xfs /dev/datastore/database   # or mkfs.ext4
sudo mkdir -p /mnt/database
echo "UUID=$(sudo blkid -s UUID -o value /dev/datastore/database) \
/mnt/database xfs defaults 0 0" | sudo tee -a /etc/fstab
sudo systemctl daemon-reload            # fstab -> systemd units
sudo mount -a
sudo chmod 1777 /mnt/database           # AFTER mounting, not before

sudo findmnt --verify                   # DO THIS BEFORE EVERY REBOOT
findmnt /mnt/database; df -h /mnt/database
Block devicesidentify by UUID=, never /dev/sdX
Network mountsadd _netdev
Flaky devicesadd nofail so boot continues

Order matters: chmod the mount point after mounting. Do it before and you've only changed the empty directory that the filesystem then hides.

SwapLab 18

Swap file

sudo dd if=/dev/zero of=/swapfile bs=1M count=512
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo semanage fcontext -a -t swapfile_t /swapfile # if ls -Z disagrees
sudo restorecon -v /swapfile
echo '/swapfile none swap defaults 0 0' | sudo tee -a /etc/fstab
sudo systemctl daemon-reload
sudo swapon -a

Swap LV (the exam's usual phrasing)

sudo lvcreate -L 256M -n swap datastore
sudo mkswap /dev/datastore/swap
echo "UUID=$(sudo blkid -s UUID -o value /dev/datastore/swap) \
none swap defaults 0 0" | sudo tee -a /etc/fstab
sudo systemctl daemon-reload
sudo swapon -a
swapon --show; free -h
  • Use dd, not fallocate — swapon rejects fallocated files on some filesystems.
  • The SELinux label matters at boot, when systemd activates the file. A wrong label shows up as an AVC after reboot.

NFS & autofsLab 6

Server

sudo dnf -y install nfs-utils
sudo mkdir -p /public /private
sudo chown -R nobody:nobody /public /private
sudo chmod 755 /public; sudo chmod 770 /private
sudo tee -a /etc/exports <<'EOF'
/public   192.168.1.0/24(ro,sync)
/private  192.168.1.0/24(rw,sync)
EOF
sudo systemctl enable --now nfs-server
sudo exportfs -rav                  # re-export all, verbose
sudo firewall-cmd --permanent --add-service={nfs,mountd,rpc-bind}
sudo firewall-cmd --reload
sudo exportfs -v

Client — static mount

sudo dnf -y install nfs-utils autofs
showmount -e 192.168.1.95
sudo mkdir -p /mnt/public /mnt/private
sudo tee -a /etc/fstab <<'EOF'
192.168.1.95:/public   /mnt/public   nfs  defaults,_netdev,ro  0 0
192.168.1.95:/private  /mnt/private  nfs  defaults,_netdev,rw  0 0
EOF
sudo systemctl daemon-reload
sudo mount -a
findmnt -t nfs4

Client — autofs, 30-second timeout

sudo mkdir -p /automount
echo '/automount /etc/auto.automount --timeout=30' \
  | sudo tee /etc/auto.master.d/automount.autofs
sudo tee /etc/auto.automount <<'EOF'
public   -fstype=nfs,ro  192.168.1.95:/public
private  -fstype=nfs,rw  192.168.1.95:/private
EOF
sudo systemctl enable autofs
sudo systemctl restart autofs       # RESTART, so maps are re-read

ls /automount                       # empty is normal -- keys appear on access
cat /automount/public/d.txt         # this triggers the mount
mount | grep /automount
sleep 40; mount | grep /automount   # gone after 30s idle

Wildcard map (exam favourite: remote home dirs)

# /etc/auto.master.d/rhome.autofs
/rhome  /etc/auto.rhome

# /etc/auto.rhome -- & is replaced by the key (the directory name)
*  -fstype=nfs,rw  192.168.1.95:/rhome/&

Traps: systemctl enable --now autofs does not reload maps if autofs was already running — restart it. Don't cd into an automount before testing the idle timeout. And chown/chmod on a client mount point is a no-op: the share's own permissions cover it.

  • nfs alone suffices for NFSv4. mountd + rpc-bind are what make showmount -e and NFSv3 work.
  • root is squashed to nobody on the client — expected.

Services & the journalall labs

sudo systemctl enable --now httpd # enable = survives reboot. Always both.
systemctl is-enabled httpd; systemctl is-active crond
systemctl status nginx --no-pager
sudo systemctl daemon-reload     # after editing fstab or unit files
journalctl -xeu nginxthe one to reach for: unit logs + explanations, jumped to the end
journalctl -u nginx -n 50last 50 lines for one unit
journalctl -b -p errall errors since boot
journalctl --since "-10min"relative window
journalctl --since "2026-10-01 15:00:00" --until "… 15:05:00"absolute window
journalctl -k -ffollow kernel messages
journalctl -t setroubleshootby syslog tag

Why -p err can hide the real reason: nginx writes its [emerg] line to stderr, which the journal stores at info priority. Filtering on err leaves you with only systemd's useless "Failed to start". Use -xeu <unit>.

Scheduling: cron & atLab 7

# append to a user's crontab without opening an editor
(sudo crontab -u harry -l 2>/dev/null; echo '*/5 * * * * /usr/local/bin/ex200.sh') \
  | sudo crontab -u harry -

sudo crontab -u harry -l
systemctl is-active crond
sudo grep CROND /var/log/cron | tail -n 3

# deny a user cron
echo natasha | sudo tee -a /etc/cron.deny
sudo su - natasha -c 'crontab -l' # "not allowed to use this program"
# field order:  min  hour  dom  mon  dow
*/5 * * * *  /usr/local/bin/ex200.sh
*/2 * * * *  logger "EX200 in progress"    # verify: sudo journalctl -t harry

# one-off jobs
sudo dnf -y install at; sudo systemctl enable --now atd
echo 'date > /tmp/at-test.txt' | at now + 2 minutes
atq

Two traps: test a deny with crontab -l, never crontab -e — if the deny isn't working, -e opens an editor and hangs. And if the job writes to a root-owned path like /var/log, pre-create the file and chown it, or the job fails silently every interval.

  • If /etc/cron.allow exists, only users listed there may use cron, and cron.deny is ignored entirely.

Time sync: chronyLab 9

Serve time

sudo tee -a /etc/chrony.conf <<'EOF'
allow 192.168.1.0/24
local stratum 10
EOF
sudo systemctl restart chronyd
sudo firewall-cmd --permanent --add-service=ntp; sudo firewall-cmd --reload
sudo chronyc clients             # who is syncing from us

Consume time

sudo sed -ri 's/^(pool|server) /#&/' /etc/chrony.conf # kill the defaults
echo 'server servera.lab.local iburst' | sudo tee -a /etc/chrony.conf
sudo systemctl enable chronyd
sudo systemctl restart chronyd   # RESTART -- it was already running
sudo timedatectl set-ntp true

chronyc sources -v               # want "^* servera" (* = selected)
chronyc tracking
timedatectl                      # "System clock synchronized: yes"

Two traps: RHEL's default config uses a pool line, not server — a sed that only matches ^server silently leaves the public pool active alongside your new source. And chronyd is already running on a fresh install, so enable --now will not reload your edited config. Always restart.

  • local stratum 10 lets the server keep serving time when it can't reach the internet.

SSH key authenticationLab 23

sudo systemctl enable --now sshd
sudo firewall-cmd --list-services       # should include ssh

sudo su - harry
ssh-keygen -t ed25519 -N '' -f ~/.ssh/id_ed25519   # -N '' = no passphrase
ssh-copy-id harry@serverb.lab.local     # last password you'll type

ssh harry@serverb.lab.local hostname
scp test.txt harry@serverb.lab.local:/tmp/

Still prompting? Fix on the server

sudo chmod 700 /home/harry/.ssh
sudo chmod 600 /home/harry/.ssh/authorized_keys
sudo chown -R harry:harry /home/harry/.ssh
sudo restorecon -Rv /home/harry/.ssh    # must be ssh_home_t
sudo journalctl -u sshd -n 20           # look for "bad ownership or modes"
ssh -v harry@serverb.lab.local          # client side

Hardening (only once keys work — keep a root session open)

echo 'PasswordAuthentication no' | sudo tee /etc/ssh/sshd_config.d/01-lab.conf
sudo sshd -t && sudo systemctl reload sshd
# undo: sudo rm /etc/ssh/sshd_config.d/01-lab.conf; sudo systemctl reload sshd
  • sshd keeps the first value it reads per setting, and drop-ins load in name order — so 01- beats the vendor's 50-redhat.conf.
  • SELinux needs no changes for normal key logins. It only bites when ~/.ssh was created with mv or copied in and kept the wrong label.

Diagnostics drillLab 24

What's listening / who's connected

sudo ss -ltnp            # -l listening -t TCP -n numeric -p process
sudo ss -ltnp 'sport = :80'
sudo ss -ltnp 'sport = :5555' # suspicious listener -> gives you the PID

sudo ss -tnp state established '( sport = :80 )'
# peer IPs. NOTE: with a state filter ss drops the State column,
# so the peer address is field 4, not 5.
ss -tn state established '( sport = :80 )' \
  | awk 'NR>1 {print $4}' | cut -d: -f1 | sort -u

Who changed a protected file

sudo auditctl -w /etc/hosts -p wa -k hosts_watch # runtime only
sudo ausearch -k hosts_watch -i
sudo ausearch -k hosts_watch -i | grep -E -o '(auid|uid|exe|comm)=[^ ]+' | sort -u
sudo auditctl -W /etc/hosts -p wa -k hosts_watch # remove the watch

# persistent across reboot:
#   /etc/audit/rules.d/hosts.rules:  -w /etc/hosts -p wa -k hosts_watch
sudo augenrules --load

auid vs uid: auid is the user who originally logged in and survives sudo and su — that's your culprit. uid is merely who the process ran as (usually root).

Failed logins

sudo ausearch -m USER_AUTH,USER_LOGIN,USER_ACCT --success no -ts recent -i
sudo journalctl --since "-15min" | grep -Ei 'authentication failure|failed password'
sudo journalctl -u sshd -n 20 --no-pager
  • Test failed logins as a normal user, not root — root's su never asks for a password.

Boot & root password resetLab 17

# At GRUB:
#   1) press 'e' on the kernel entry
#   2) append to the linux line:   init=/bin/bash enforcing=0
#   3) boot with Ctrl+x (or F10)

mount -o remount,rw /     # so the change can actually be saved
passwd root
touch /.autorelabel        # relabel on next boot -> correct /etc/shadow context
sync
exec /sbin/reboot -f

init=/bin/bash starts a root shell as PID 1. rd.break no longer works on current RHEL. Skip /.autorelabel and SELinux will deny reads of the new /etc/shadow.

Essential tools: find, tar, scriptsLabs 10, 12, 16

find & copy

sudo mkdir /root/find_large_files
sudo find / -xdev -type f -size +4M -exec cp {} /root/find_large_files/ \;

# variants
sudo find / -user harry -type f -exec cp {} /root/harry_files/ \;
sudo find /usr/share -type f -size +30k -size -50k
sudo find / -xdev -nouser
-xdevstay on one filesystem — skips /proc (whose kcore reports terabytes), /sys, /boot, NFS
{}replaced with each file find matches
\;ends the -exec command; the backslash stops the shell from eating the ;

The -size trap: find -size -1M matches only empty files. find rounds sizes up to whole units, so "less than one 1-MiB unit" means 0. For exact limits use bytes: -size -1048576c.

Archive & compress

sudo tar -cjf /root/backup.tar.bz2 /usr/local
sudo file /root/backup.tar.bz2             # bzip2 compressed data
sudo tar -tjf /root/backup.tar.bz2 | head  # list
sudo tar -xjf /root/backup.tar.bz2 -C /root/restore # extract to a separate dir (must exist)
sudo tar -xjf /root/backup.tar.bz2 -C /          # restore to original location (overwrites)
sudo restorecon -Rv /usr/local             # fix SELinux labels after restoring in place
  • Mnemonic: z = gzip (.gz), j = bzip2 (.bz2), J = xz (.xz). Use the one the task asks for.
  • If -j fails, dnf -y install bzip2.
  • As root, extract keeps owner, group, mode, and timestamps. As a user, add -p to keep modes. SELinux contexts and ACLs need --selinux --acls on both create and extract.

  https://dl.flathub.org/repo/flathub.flatpakrepo
